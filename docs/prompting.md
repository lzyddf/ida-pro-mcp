# 提示词工程

大模型可能产生幻觉，因此逆向分析任务应明确说明目标、证据要求和允许的操作。整数、字节和大小端转换尤其容易出错。下面是一份最小示例：

> 你的任务是在 IDA Pro 中分析一个 crackme。你可以使用 MCP 工具获取信息。总体遵循以下策略：
>
> - 阅读反编译结果，并用注释记录有证据支持的结论。
> - 将变量重命名为更容易理解的名称。
> - 必要时修正变量和参数类型，尤其注意指针和数组类型。
> - 将函数重命名为能够描述其作用的名称。
> - 需要更多细节时查看函数反汇编，并补充分析注释。
> - 不要自行转换进制；需要时始终调用 `convert_number` MCP 工具。
> - 不要暴力破解，应从反汇编结果和简单 Python 脚本中推导答案。
> - 最后创建 `report.md`，记录结论、证据和分析步骤。
> - 找到解答后，先把得到的密码展示给用户并请求反馈。

如果未使用 `--unsafe`，类型修改、补丁和调试工具不会出现在工具列表中。提示词不应要求模型反复调用不存在的工具；需要这些能力时，应由用户明确重新生成带 `--unsafe` 的配置，并理解相应风险。

## 提高准确率的建议

- 明确要求模型区分“IDA 返回的事实”“从代码推断的结论”和“尚未验证的猜测”。
- 数学运算和整数/字节转换优先使用 `convert_number`；运算密集型任务也可以额外配置 [math-mcp](https://github.com/EthanHenrickson/math-mcp)。
- 优先使用 `decompile_function_text` 和 `disassemble_function_text` 获取紧凑上下文，只有需要逐行地址映射时才使用结构化版本。
- 让模型先查看入口点、导入、字符串、段和调用关系，再深入单个函数，可以减少无目的调用。
- 要求模型在重命名或写注释前说明证据，避免把早期猜测固化进 IDB。

大模型通常不擅长直接处理高度混淆的代码。开始分析前，可以先处理：

- 字符串加密
- 导入哈希
- 控制流平坦化
- 代码加密或运行时解密
- 反反编译技巧

还可以使用 Lumina 或 FLIRT 识别开源库代码和 C++ 标准库，减少模型在已知库函数上的上下文浪费。
